# Waterius Integration for Home Assistant

[![hacs_badge](https://img.shields.io/badge/HACS-Custom-orange.svg)](https://github.com/custom-components/hacs)
[![GitHub Release](https://img.shields.io/github/release/alexanderznamensky/waterius.svg)](https://github.com/alexanderznamensky/waterius/releases)
[![License](https://img.shields.io/github/license/alexanderznamensky/waterius.svg)](LICENSE)

Пользовательская интеграция **Waterius / Ватериус** для Home Assistant.

Интеграция умеет получать данные счётчиков из [account.waterius.ru](https://account.waterius.ru), сопоставлять их с накопительными датчиками Home Assistant и автоматически передавать актуальные показания обратно в Waterius.

Проверено на счётчиках **холодной и горячей воды**, а также **электроэнергии T1/T2/T3**. Поддержка газа, отопления/тепла, питьевой воды и других типов предусмотрена, но пока не проверена на реальных приборах.

*Home Assistant integration for reading meter data from Waterius and sending cumulative Home Assistant readings back to Waterius.*

---

## Возможности / Features

- 📥 Получение устройств, каналов, показаний и статусов из Waterius
- 📤 Автоматическая отправка накопительных показаний из Home Assistant в Waterius
- 🔄 Единый период синхронизации: по умолчанию **20 минут**
- 🔎 Автоматическое определение сценария настройки:
  - если счётчики уже есть в Waterius — используются существующие каналы;
  - если аккаунт пустой — запускается мастер первоначальной настройки
- 🔗 Сопоставление каналов Waterius с `sensor.*` и `input_number.*` Home Assistant
- 💧 Поддержка ХВС и ГВС
- ⚡ Поддержка однотарифных, двухтарифных и трёхтарифных электросчётчиков
- 🔥 Подготовлена поддержка газа, отопления/тепла, питьевой воды и других типов счётчиков
- 🧮 Проверка выбранных источников перед созданием счётчиков
- 🔁 Автоматическое преобразование единиц:
  - `L` → `m³`
  - `Wh` → `kWh`
  - `MWh` → `kWh`
- 🛑 Защита от выбора очевидно мгновенных датчиков расхода/мощности, например `L/min`, `m³/h`, `W`, `kW`
- 📅 Диагностические данные по отправке показаний и срокам оплаты, если они доступны в Waterius
- 🔘 Кнопка **«Обновить данные»**
- ☁️ Кнопка **«Отправить показания сейчас»**

- 🇷🇺 Русский интерфейс
- 🎨 Встроенные brand-иконки и логотип для светлой и тёмной темы

## Как работает синхронизация

Интеграция использует один общий интервал синхронизации.

По умолчанию каждые **20 минут**:

1. если настроены источники Home Assistant — интеграция отправляет их текущие накопительные значения в Waterius;
2. после отправки обновляет данные из Waterius;
3. если отправлять нечего — просто обновляет данные из Waterius.

Интервал можно изменить в настройках интеграции. Допустимый диапазон: **1–1440 минут**.

Отдельная automation Home Assistant для периодической отправки показаний не требуется.

## Установка / Installation

### Через HACS — рекомендуется

1. Откройте **HACS** в Home Assistant.
2. Нажмите на три точки в правом верхнем углу.
3. Выберите **Custom repositories**.
4. Добавьте репозиторий:
   - URL: `https://github.com/alexanderznamensky/waterius`
   - Category: `Integration`
5. Найдите **Waterius / Ватериус** в HACS.
6. Нажмите **Download**.
7. Перезапустите Home Assistant.

### Вручную

Скопируйте папку:

```text
custom_components/waterius
```

в:

```text
/config/custom_components/waterius
```

После этого перезапустите Home Assistant.

## Настройка / Configuration

### 1. Регистрация и получение токена Waterius

Если аккаунта ещё нет, зарегистрируйтесь:

[https://account.waterius.ru/register](https://account.waterius.ru/register)

После входа в Waterius откройте:

[https://account.waterius.ru/api/user/token/](https://account.waterius.ru/api/user/token/)

Скопируйте API token.

### 2. Добавление интеграции в Home Assistant

Откройте:

**Настройки → Устройства и службы → Добавить интеграцию → Ватериус**

Введите:

- **Название** — по умолчанию `Waterius`
- **Токен Waterius**
- **Период синхронизации с Waterius** — по умолчанию `20` минут

После проверки токена интеграция сама определит, есть ли в аккаунте Waterius счётчики.

## Сценарий 1: счётчики уже есть в Waterius

Если `/api/channel/` уже содержит каналы, интеграция не создаёт новые устройства и счётчики.

Для каждого найденного канала мастер покажет:

- тип счётчика;
- серийный номер;
- соответствующий канал Waterius;
- поле выбора источника Home Assistant.

Можно выбрать накопительный:

```text
sensor.*
```

или:

```text
input_number.*
```

Если конкретный канал не нужно автоматически отправлять из Home Assistant, поле можно оставить пустым.

После завершения настройки существующие каналы Waterius продолжают использоваться без пересоздания.

---

## Сценарий 2: новый пустой аккаунт Waterius

Если в аккаунте нет каналов, запускается мастер первоначальной настройки.

### Выбор типов счётчиков

Можно выбрать:

- Холодная вода
- Горячая вода
- Электроэнергия
- Газ
- Отопление / тепло
- Питьевая вода
- Другой счётчик

> Газ, отопление/тепло, питьевая вода и тип «Другой» предусмотрены в интеграции, но пока не проверены на реальных приборах.

### Электроэнергия

Для электросчётчика выбирается тарифность:

- **Однотарифный** — общее показание
- **Двухтарифный** — день / ночь
- **Трёхтарифный** — T1 пик / T2 ночь / T3 полупик

Для одного физического электросчётчика серийный номер вводится один раз, а каждой тарифной зоне сопоставляется отдельный датчик Home Assistant.

### Источники Home Assistant

Для каждого показания выбирается накопительный датчик:

```text
sensor.*
```

или:

```text
input_number.*
```

Например:

```text
ХВС        → input_number.hvs
ГВС        → input_number.gvs
T1 / пик   → sensor.energy_t1
T2 / ночь  → sensor.energy_t2
T3 / полупик → sensor.energy_t3
```

Перед созданием счётчиков интеграция показывает текущие значения и проверяет, что выбранные сущности доступны и содержат числовые накопительные данные.

## Создание устройства Home Assistant в Waterius

Для каждой логической группы счётчиков мастер попросит создать устройство Home Assistant в Waterius.

Откройте:

[https://account.waterius.ru/devices/add/home-assistant](https://account.waterius.ru/devices/add/home-assistant)

Нажмите **«Создать устройство»**.

Waterius сразу покажет уникальный `key`.

Скопируйте его и вставьте в мастер Home Assistant.

После первого принятого запроса Waterius создаёт каналы счётчиков. При необходимости интеграция автоматически повторяет bootstrap-запрос тем же `key`, пока Waterius не заполнит метаданные каналов.

Для разных групп используется отдельный `key`. Например:

```text
Вода             → отдельное устройство / key
Электроэнергия   → отдельное устройство / key
Газ              → отдельное устройство / key
```

Новый `key` не нужно создавать при каждом обновлении показаний — он сохраняется в настройках интеграции и используется автоматически.

## Сущности / Entities

### Сенсоры счётчиков

Для каждого канала Waterius создаётся сенсор.

Поддерживаемые типы:

| Тип | Единица |
|---|---|
| ХВС | `m³` |
| ГВС | `m³` |
| Электроэнергия | `kWh` |
| Электроэнергия — день | `kWh` |
| T1 — пик | `kWh` |
| T2 — ночь | `kWh` |
| T3 — полупик | `kWh` |
| Газ | `m³` |
| Питьевая вода | `m³` |

Для отопления/тепла и типа «Другой» единица зависит от данных Waterius и конкретного сценария использования.

### Атрибуты сенсоров

В зависимости от данных Waterius могут отображаться:

- Серийный номер
- Статус отчёта
- Дата поверки
- Предупреждения
- Значение в предыдущем периоде
- Значение в текущем периоде
- Время передачи в УК
- Время последней передачи в Waterius

---

## Диагностический сенсор «Сводка»

Сенсор **«Сводка»** относится к служебному устройству `Waterius`.

Его состояние — количество источников (`source`) в аккаунте Waterius.

Например:

```text
Счётчики воды          → source 1
Счётчик электроэнергии → source 2

Сводка = 2
```

Атрибуты:

- `sources_count` — количество источников Waterius
- `channels_count` — общее количество каналов
- `exports_count` — количество настроек передачи в УК / export

---

## Диагностические данные по оплате

Если канал Waterius связан с `export`, интеграция создаёт диагностический сенсор **«Срок оплаты»**.

В его атрибутах могут присутствовать:

- Название устройства
- УК
- Лицевой счёт
- Дата отправки
- Телефон пользователя
- Дней до оплаты
- Время последней передачи в Waterius

## Кнопки / Buttons

### «Обновить данные»

Принудительно перечитывает актуальные данные из `account.waterius.ru`.

Показания из Home Assistant при этом не отправляются.

### «Отправить показания сейчас»

Немедленно читает все сопоставленные `sensor.*` / `input_number.*`, отправляет их в Waterius и затем обновляет данные интеграции.

## Сервисы / Services

### `waterius.send_all`

Основной сервис ручной отправки.

Читает текущие значения всех сопоставленных сущностей Home Assistant и отправляет их в Waterius.

```yaml
action: waterius.send_all
```

Если настроено несколько экземпляров интеграции Waterius, можно указать `entry_id`:

```yaml
action: waterius.send_all
data:
  entry_id: "CONFIG_ENTRY_ID"
```

### `waterius.send_reading`

Отправляет значение напрямую в уже существующий канал Waterius по `channel_id`.

```yaml
action: waterius.send_reading
data:
  channel_id: 55170
  value: 162.5
```

Параметры:

- `channel_id` — ID существующего канала Waterius
- `value` — накопительное показание

### Сервисы совместимости

Для совместимости со старыми версиями сохранены:

```text
waterius.send_configured_reading
waterius.send_all_to_waterius
```

Оба выполняют ту же основную операцию, что и `waterius.send_all`: отправляют текущие сопоставленные значения Home Assistant.

Для новых автоматизаций рекомендуется использовать:

```text
waterius.send_all
```

## Настройки после установки

Через **Настроить** у записи интеграции можно:

- изменить API token;
- изменить период синхронизации;
- заново сопоставить существующие каналы Waterius с `sensor.*` / `input_number.*`.

Изменять `key` универсальных устройств при обычной эксплуатации не требуется.

## Устранение неполадок / Troubleshooting

### Не удаётся проверить token

Проверьте token на странице:

[https://account.waterius.ru/api/user/token/](https://account.waterius.ru/api/user/token/)

и убедитесь, что Home Assistant имеет доступ в Интернет.

### Счётчики не появились после первого запроса

Для нового устройства Waterius иногда сначала создаёт служебный канал, а метаданные каналов появляются после повторной отправки.

Интеграция версии 1.1.12 автоматически выполняет bootstrap-повтор тем же `key` и проверяет появление ожидаемых `data_type + serial`.

Не создавайте новое устройство Waterius при первом промежуточном состоянии.

### Датчика нет в выпадающем списке

Для источников поддерживаются:

```text
sensor.*
input_number.*
```

Другие домены в мастере не показываются.

### Выбран неправильный тип датчика

Waterius ожидает накопительное показание счётчика.

Подходят, например:

```text
125.43 m³
74833 kWh
```

Не подходят мгновенные значения:

```text
6.4 L/min
0.7 m³/h
560 W
3.2 kW
```

### Данные не обновляются

Проверьте:

1. подключение Home Assistant к Интернету;
2. доступность `account.waterius.ru`;
3. состояние исходных `sensor.*` / `input_number.*`;
4. журнал Home Assistant.

Для расширенной диагностики можно временно включить:

```yaml
logger:
  logs:
    custom_components.waterius: debug
```

## Ограничения / Limitations

- Настройка конкретной управляющей компании / ресурсоснабжающей организации (`export`) автоматически не создаётся.
- Интеграция умеет читать существующие `export` и связанные диагностические данные.
- Автоматическое создание и передача проверены на воде и многотарифной электроэнергии.
- Газ, отопление/тепло, питьевая вода и тип «Другой» реализованы, но требуют дополнительного тестирования на реальных аккаунтах и приборах.
- Для работы интеграции требуется подключение Home Assistant к Интернету.
